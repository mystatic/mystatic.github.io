ENPIRE：机器人怎样通过真实实验改进策略

机器人 · 技术解读 · 发布于 2026.11.16 · 架构图与 9 段官方演示

研究目的

机器人要把一根销钉插进孔里。一次失败后，下一次该怎么办？可以修改搜索轨迹，可以增加示范，可以继续强化学习，也可以检查是不是控制偏差导致每次都卡在同一个位置。困难在于：这些尝试需要反复复位场景、判断结果、保留数据、诊断失败，再决定修改什么。过去，这些工作往往由研究人员衔接。

ENPIRE 的研究目标，是把这套真实世界实验过程组织成编码 Agent 能持续操作的闭环。 它研究的对象既包括机器人策略，也包括“发现一个更好策略的过程”。把这两件事分开，才能看懂论文中的自主研究、在线学习和失败重试各自发生在哪里。论文 §1–2

本文围绕插销任务展开，读完应能回答五个问题：为什么先建环境；Agent、学习器与机器人分别做什么；一条轨迹怎样改变策略；一次策略输出怎样到达机器人并得到核验；哪些实验支持机制、哪些证据仍不充分。

一句话结论

ENPIRE 将经过人类反馈建立的复位、验证和控制接口固定下来，使编码 Agent 能依据真实机器人实验，搜索程序策略、学习算法及训练配置，并通过再次执行检验改进。 论文支持的是在特定任务与环境条件下的自主策略研发；“自主”成立的范围，需要连同环境准备、数据来源、重试协议和评估方式一起读。论文 §2

问题动机

为什么只让大模型生成动作或代码还不够

假设 Agent 写出一段“定位孔口、对齐、下压”的程序。程序能运行，只能说明调用顺序基本成立。如果销钉滑了、孔口被挡住、下压方向偏了，研究者还需要知道：究竟哪一步失败，怎样让场景回到可比较的起点，以及下一次修改是否真的更好。

仿真常把这些能力封装为现成接口。真机却需要在物理世界完成复位，成功判定也依赖传感器和阈值。摩擦、接触、相机遮挡、装夹状态都会随时间和硬件变化。因而，数字环境里能反复改程序的 Agent，直接接上机械臂后并不会自动获得可靠的实验流程。论文 §1、§3.1

ENPIRE 选择先建设实验环境，再开放策略侧的改进空间。这使“我觉得新方案更好”可以转化为“在同一复位与评分条件下，重新执行并比较结果”。其核心贡献是把物理研究闭环做成可操作的系统；BC、RL、运动规划等方法是可被它调用和修改的组成部分。

环境为何必须能复位、能判断、能约束

复位决定下一次实验从哪里开始。 插销失败后，销钉可能仍在夹爪里、已经落到桌上，也可能半插在孔中。固定复位程序需要识别状态，取出或重新拾取对象，再返回合适的悬停位置。论文列举了 SAM3 分割、BundleSDF 位姿跟踪、cuRobo 规划和夹爪力矩检查等工具；不是所有工具都被每个任务使用。附录 A.1

验证决定学习的方向是否正确。 插销图 9 的判定组合了视觉对齐、从本体状态得到的插入深度，以及关节力矩推算的接触信息。只看图像中的投影重合可能把“在孔上方悬空”判为成功；只看末端降低又可能把“在孔外下压”判为成功。组合信号的目的，是排除这些不同的假阳性。

可以用下面的教学形式化概括多条件成功判定。视觉对齐、插入深度、接触状态分别通过既定检查时，输出成功：

rt=𝟏[At∧Dt∧Ft]

这里 t 是被检查的观测时刻；A、D、F 分别表示三类检查的布尔结果。它们由固定验证程序计算，而不是由 critic 预测。接触检查的确切数值范围、滤波与标定参数为 UNKNOWN_FROM_PAPER；不能把“检测到力”简单替换为“力越大越成功”。

约束决定什么尝试可以发生。 论文设置可操作的构型和运动范围，违反限制导致失败、终止或截断，并触发复位。关节控制和夹爪限力由下层承担。编码 Agent 在研究阶段不能通过放宽边界来获得更高分。论文 §2.1、附录 B.3

这一环境设计首先要保证评分与起点可信；环境证据审查将检查作者实际验证了什么，以及还缺哪些可靠性指标。

用一次插销失败区分三层循环

图解：最上层决定“试什么方法”，中间层在需要时“用数据更新网络”，最下层负责“真正动起来并获得反馈”。三层可以交错运行，更新的对象却不同。一个机器人反复尝试，不代表它每次都更新了模型；一个 Agent 改好了代码，也不代表基础大模型的权重发生了变化。

教学重建。 机器人向下插入，销钉接触孔边，验证器仍返回未成功。此刻有三种完全不同的后续：

  1. 执行层恢复：固定程序根据当前观测抬起一点、重新对准再试。这一过程可以不改任何权重，也不改程序。
  2. 参数层学习：轨迹进入缓冲区，学习器更新 critic 和策略，使以后在相似观测下更倾向于合适动作。更新发生在批次优化时，不一定紧跟这一次动作。
  3. 研究层修改：Agent 发现多次尝试都在同一方向卡住，提出调整训练目标、数据混合或控制补偿的假设，改代码，再启动可比较的实验。

训练数据流

神经策略路线：原始轨迹 → 完整性与时间对齐 → 来源分流／预处理 → 训练批次 → BC 或 RL 目标 → 参数更新 → 发布并复验。 这里跟随一条插销轨迹，不把不同论文实验的配置合并成一个虚构的统一训练配方。

  1. 部署层记录一次交互。 输入是传感器观测、实际使用的动作和环境结果，输出是逐步状态张量、同步相机视频、动作来源与奖励等记录。图像、状态和动作是已记录量；成功信号是验证器自动产生的量。论文提到来源包含 RL、人工及手动控制，不应把所有轨迹叫作无人干预数据。记录按交互步骤推进，轨迹按 episode 归档。附录 B.5
  2. 轨迹完成后进入可读取状态。 后台读取器检查文件和数据，再转换为训练转移。公开代码处理了奖励延迟：若成功对应过去的一帧，相关路径会把奖励和终止对齐到被评分的时刻，并裁掉后续帧，而不是把晚收到的成功消息随意记在最新动作上。该机制是公开实现中的通用异步奖励路径，不能自动认为论文每项任务都使用了它。异步奖励实现
  3. 按动作来源分流，再做表示转换。 论文的典型路由是 RL 动作进在线回放区，人工／手动动作进示范区。代码按逐步来源标签路由，并有严格检查和配置开关。来源标签回答“谁做了这个动作”，奖励回答“结果是否成功”；这是两条不同的信息。预处理还会选择相机和本体状态、变换动作尺度；舍弃的观测不再直接供网络使用。读取器
  4. 学习器抽取批次。 公开训练入口在开始采样时已有示范数据的情况下，构建在线与示范各占一半的批次；没有示范时使用在线数据。插销配置给出的批量大小是 1024，因此这一配置分支可对应 512 条在线转移加 512 条示范转移。这里的分母是训练样本条数，不是成功 episode 的比例；原论文每次搜索运行的混合比例仍需各自配置。训练入口
  5. 根据选定路线计算损失并更新。 BC 使用记录动作作为模仿目标；RL 使用记录的奖励、下一观测以及模型估计的价值构造更新目标。公开插销配置冻结视觉编码器，策略、critic 及可训练投影的具体更新取决于训练路线。BC 路径更新 actor，critic 与温度不更新；RL 路径分别更新这些网络。没有证据表明编码大模型因这次训练而更新权重。SACMini 实现
  6. 发布候选策略，回到真实环境验证。 学习器周期性发布网络参数，actor 进程接收；图像编码、动作推理与环境执行继续发生。损失下降只说明训练目标改善，候选策略还要用固定评分条件重新运行。实验结果交给研究外循环决定保留什么。参数同步节拍按训练步配置，不等同于机器人控制频率。训练入口

程序策略路线则是：轨迹、视频和结果 → Agent 诊断 → 修改程序／参数 → 固定环境重跑 → 保留或放弃修改。这里也能发生学习意义上的能力改进，但可以完全没有梯度、critic 和策略网络。报告中的“训练数据流”必须容纳这条分支，而不能给它强行套上 RL 损失。

推理数据流

一次执行：当前观测 → 策略输出／程序调用 → 动作转换与控制 → 物理响应 → 固定验证器 → 继续、恢复或终止。 神经策略在运行时不需要未来成功标签；那些标签是在动作发生后产生，再用于评分或后续训练。

  1. 复位程序建立并检查起点。 对插销，准备到合适的持物与悬停状态。输入是场景及机器人状态，输出是可开始学习阶段的初始观测。由固定环境负责，每个新 episode 开始时执行；复位失败不能冒充一次正常策略试验。论文 §2.1、图 9
  2. 部署层提供当前观测。 论文平台包含顶部及双腕相机，策略使用视觉与本体状态；拥有三台相机不意味着某个策略吃进全部图像。公开插销配置选择右腕图像，以及右臂高度、旋转表示和夹爪状态；通用远程环境配置把模型图像尺寸设为 256×256。该选择舍弃了部分场景和状态信息，不能把网络理解为直接读取完整三维真值。插销配置
  3. actor 进程运行策略网络。 这一公开配置输出右臂末端的三个归一化位置增量，随后裁剪、缩放。算法动作是三维；发送给远程环境的格式补入固定旋转与夹爪，成为十维表示。补出的维度不是策略又学会了七个控制自由度。右臂配置
  4. 桥接层把动作交给机器人控制。 公开实现可把单个动作重复封装为带执行长度的数组。这不是网络预测了彼此不同的未来动作序列。控制系统还需要把末端目标落实到关节目标；论文没有完整给出该插销路线的 IK、插值与每层调度对应关系，这条边标为 UNKNOWN_FROM_PAPER。动作桥接实现
  5. 低层控制驱动真实关节。 论文报告策略频率 30 Hz、CAN 上的关节控制频率 100 Hz；六个臂关节用 PD 加重力补偿，夹爪使用限力矩的柔顺夹持。目标到达与否受动力学、接触和延迟影响。30 Hz 与 100 Hz 是论文平台描述，不能从代码默认打包长度倒推出某条实验的实际推理频率。附录 B.2–B.4
  6. 验证器与状态机决定下一步。 新图像、深度相关状态与接触信息用于判定；未成功可以继续动作或恢复，成功、超时或越界则按规则结束并复位。运行期间也可以保存轨迹供后续研究，但恢复动作本身不要求 Agent 再写代码或 learner 当场更新权重。每种失败的完整重试上限、时间预算与分支细节，应以具体任务规则为准，未披露部分不补猜。

两类改进路线：程序、BC 与 RL 分别怎样学

程序搜索：改的是可执行决策规则

程序可以组织“定位目标 → 选择接触位置 → 调用规划器 → 观察结果 → 调整后再试”。在 Push-T 上，Agent 通过合成感知与控制工具调用探索启发式策略。每次候选程序完成实验，Agent 读取轨迹和分数，再修改动作规则、阈值或调用顺序。论文 §3.1

教学重建。 如果 T 形物体只移动却不旋转，程序可能需要换接触点，而不是增加下压力。要确认这个解释，需要接触位置、轨迹与目标姿态的证据；如果只给“失败”一个比特，Agent 很难区分定位错了和接触策略错了。细粒度日志因而影响研究效率。

这一分支的监督是实验结果与诊断证据，更新由编码 Agent 生成的代码完成。它没有必须存在的反向传播损失；E 模块的“演化”也不应被默认画成论文未给出的固定种群算法或中心调度器。

观看重点。 看推动方向和接触位置如何随 T 形块的姿态变化，再回想程序路线的“观察—定位—规划—执行—重看”。这是本文主线插销之外的补充任务，帮助理解工具调用如何落到物体运动。官网另有可切换初态与 Agent 的 Push-T 轨迹交互；本教程选择对应的执行视频，并未把该交互的所有分支复制进来。

BC：先学会像已有有效动作那样做

行为克隆解决的是：给定类似观测，策略能否输出记录中的动作。来源可以是人类示范，也可以是筛选后的策略轨迹；具体由什么筛选得到，要看实验。在线收集再加入模仿数据，可形成迭代 BC，但“把失败动作不加区分地全部模仿”并不是自然得到的改进规则。

公开实现中的 BC 使用动作的负对数似然：让记录动作在策略分布下变得更可能。

ℒBC(θ)=−𝔼(o,adata)∼𝒟[log⁡πθ(adata|o)]

这里 o 和数据动作来自记录，数据集是选定的训练样本；θ 是正在更新的策略参数。对连续动作，策略给出的是概率密度，不能把密度值直接理解为某个离散动作的成功概率。该目标不需要知道未来奖励，也不需要 critic；数据质量、覆盖范围与动作尺度却直接影响它学到的行为。代码将接近动作裁剪边界的标签略微收回，以使分布的对数密度可计算。SACMini 的 BC 路径

插销中，示范可以提供“靠近孔后如何小幅修正”的起点。若部署中出现示范没覆盖的偏移，策略可能仍失败；这说明仅优化模仿损失不保证恢复能力。ENPIRE 的研究外循环可以尝试增加相关数据、修改表示，或转向利用结果反馈的 RL。

RL：奖励只告诉结果，价值学习把结果传回此前动作

插入成功时才得到正奖励，之前的小幅修正怎样获得学习信号？第一步是把一次动作的前后观测与结果组成转移记录：

(ot, at, rt, ot+1, mt)

观测、动作与奖励来自轨迹，m 是是否继续自举的掩码。critic 输入当前观测和动作，估计继续按策略行动时的预期回报。它的输出是训练出来的预测；验证器输出则是对实际结果的检查。critic 再自信，也不能替代物理核验。

公开 SACMini 路径采用目标 critic 构造 TD 目标。下面对应关闭熵回传的配置分支：

at+1∼πθ(⋅|ot+1)yt=rt+γmtminj⁡Qϕ‾,j(ot+1,at+1)
ℒQ(ϕ)=𝔼t,j[(Qϕ,j(ot,at)−yt)2]

γ 是折扣系数；φ 是待更新 critic 的参数，带横线的参数来自缓慢跟随的目标网络，j 表示 critic 集合中的成员。当前奖励和下一观测已被记录；下一动作由当前策略采样，后续价值由目标网络估计。TD 目标在下一观测可得时即可构造，不要求真的观察直到 episode 最终结束；磁盘读取实现仍可能等待整个 episode 完整写入。

终止边界必须显式处理。m 为 0 时，目标只剩当前奖励。公开 actor 的在线转移路径把 terminated 或 truncated 都作为边界关掉自举；不能因此宣称所有离线读取路径或论文的所有训练方案都采用完全相同的截断规则。训练入口与 SACMini

教学算例，不是论文实测。 假设一条三步轨迹前两步没有奖励，第三步成功并终止，折扣取 0.99。完整轨迹结束后，可计算实际折扣回报：

(r0,r1,r2)=(0,0,1)Gt=∑k=t2γk−trk
(G0,G1,G2)=(0.9801,0.99,1)

这些是“后来真的发生了什么”的回报。当前代码配置关闭了 Monte Carlo return 目标，因此此处 G 仅用于说明稀疏成功信号的时间含义，不能把它写成这条默认更新实际采用的监督。

再看一个 TD 更新：若当前步奖励为 0、尚未终止，目标 critic 对下一动作的两个估计分别为 0.4 与 0.6，则采用较小值后，目标为 0.396。假设当前 critic 估计为 0.2，其单项平方误差约为 0.0384。

yt=0+0.99×1×min⁡(0.4,0.6)=0.396
(0.2−0.396)2=0.038416

学习器通过降低该误差，让当前动作的价值估计更接近目标。多次采样和更新逐步传播成功信息。所有小数均为教学构造，不能解读为论文 critic 的真实预测或校准后的成功概率。

策略如何利用 critic，又为什么会加入 BC 约束

critic 学会评分后，策略可尝试输出评分更高的动作。公开 SACMini 的策略目标还保留熵项，鼓励一定的动作分布宽度；其策略损失可概括如下：

Qϕ(o,a)=1M∑j=1MQϕ,j(o,a)ℒactor(θ)=𝔼o,a∼πθ[αlog⁡πθ(a|o)−Qϕ(o,a)]

α 是熵权重，由温度相关更新调节；M 是 critic 数量，Q 上的横线表示各成员的平均。这里使用的是 critic 平均值，而上面的目标回传使用最小值，这是公开代码里的具体区别。策略更新利用 critic 对动作的估计，仍需真实 rollout 验证，尤其要防范在数据覆盖不足处“利用了错误高分”。

BC 正则的直觉是：向高价值动作改进时，也保留靠近已有有效动作的倾向。论文报告搜索到的 BC 正则节点带来了进展。下面只是机制层面的教学示意，不是作者公布的完整实验损失：

ℒhybrid=ℒRL+λℒBC

λ 决定模仿约束的强弱。过强可能限制适应，过弱可能丢掉有效行为；应通过同一环境中的实验选择。公开快照提供单独的 BC 更新和 SACMini 更新，但其默认 RL 策略损失未直接加上上述 BC 项；因此论文中的“BC 正则实验”与当前默认路径应分别描述，不能仅因有 demo buffer 就断言启用了 BC 正则。

这条奖励链的终点是什么？ 对已核查的 SACMini 路线，是环境结果 → 奖励 → TD 目标 → Q 估计 → actor 更新。没有必要补入 PPO 的 GAE、优势排序或二元条件标签；这些不是本文核查到的默认更新步骤。训练批次中“示范占一半”也不代表“一半 episode 成功”。

这些训练机制让 Agent 有更多可尝试的修改，但“有这个选项”不等于“它带来了独立收益”。后面的插销研究实验区分整段研究的进步、具体方案节点和仍缺少的受控消融。

怎样检验。 附录 A.2 的扎带穿扣例子以几分钟带成功／失败标签的资料构建隔离评估集，要求 Agent 满足精确率、召回率与推理延迟要求。精确率关心“判成功的样本里有多少真的成功”，召回率关心“真实成功中有多少被识别”。Agent 可改变分割提示词、裁剪和几何阈值；评估指标计算不允许修改，资料可用于分析失败，但禁止用于训练。若误报、漏报和响应时间都达到要求，才支持将它用于奖励。这里检验的是评分程序，并没有训练机器人策略。

连续成功与带恢复成功分别说明什么

连续成功用于检查插销策略在一段评估窗口中是否稳定。公开评分器区分所有 episode 和动作来源全为 RL 的 episode；纯 RL 窗口不足 50 时不输出完整窗口成功率，人工参与的 episode 会被过滤。因此读 50/50 时应同时看完整时间线。挑出一个达到全成功的窗口，也不等于冻结后的策略在新条件下不会失败。评分实现

最强的共同结论是：在已准备好的物理反馈接口和所列任务内，ENPIRE 可以让编码 Agent 搜索程序或训练方案，并把更多实验资源转化为更快的策略研究。视觉入口和工具层感知会影响这个过程，运行时组合也可能改善整体执行。更强的主张——无需环境准备、各组件都有独立收益、经验迁移有稳定量化增益、资源成本同时下降——仍没有同等充分的受控证据。后面的建议实验专门区分“更多试验”“更好的既有算法”和“Agent 有效诊断”各自的贡献。

从证据可以进一步划出的边界

工程判断：自动复位与自动评分是能力前提，也是潜在误差源。 复位分布漂移，会让相邻两轮不再可比；验证器误报，会同时污染奖励和成绩。固定规则阻止研究 Agent 改分，但固定本身不能保证规则正确。需要独立核验、保存失败案例以及对边界情况的检查。

工程判断：关键阶段的高成功率不等于全流程可靠性。 抓取、交接、准备、插入、取出和复位各有失败可能。学习聚焦插入阶段非常合理，报告系统能力时却应同时给出起点条件、复位耗时和复位成功率。各阶段的失败也可能相关，不能未经验证就把局部成功率相乘成全流程成绩。

证据缺口：原实验配置与公开快照的对应不完整。 每条曲线的完整演示量、权重起点、策略版本、奖励阈值、重试成本及独立重复次数，不能仅凭当前仓库完全恢复。公开代码既支持人工数据，也有纯 RL 统计；工具支持某种模式，不证明论文所有运行都采用或排除了它。

证据缺口：跨任务与长期自治的覆盖有限。 文字经验迁移、数小时研究和多个接触任务，不足以证明任意任务的开放式自我进化、跨天永久记忆或无需维护的工业系统。论文没有给出本文所需的完整中断恢复、长期老化与任意物体故障覆盖证据。

下一项最能区分解释的实验

建议或假设。 在一个固定插销环境中，预先锁定复位、验证器、起始数据和资源预算，比较：固定 BC 基线、固定 RL 配方、Agent 只改程序、Agent 可改训练方案。每条路线用多个独立研究运行，并在研究结束后冻结候选策略，在未参与选择的初始条件上评估首次成功、带恢复成功、完成时间、总尝试数、人工介入与复位失败。

这个对照可以区分“性能提升主要来自更多试验”“来自某个既有强算法”与“来自 Agent 对反馈的有效诊断和方案选择”。若带恢复成绩提高但首次成功与耗时没有改善，贡献主要在恢复；若只在搜索所用场景提高，则仍需处理评估适应问题。这是后续研究建议，本教程没有执行该实验。

对 VLA/机器人落地的意义

ENPIRE 提供了一个有用的系统分工：VLA 或其他策略负责特定的观测到动作映射，编码 Agent 可以在更慢的时间尺度上组织实验、定位问题、改进策略或模块组合。是否把某项问题交给更大的模型、更多数据、程序工具或控制改进，应由失败证据决定。

验证与恢复 固定成功判定、失败检测、重试与复位 假阳性、复位失败、恢复耗时和终止条件
研究与更新 假设、试验、数据、代码、参数及经验总结 版本归属、留出评测、预算和成果保留标准

最值得迁移的原则是：让每次试验产生可比较、可追溯、可用于下一次决策的证据。 对已有 VLA 系统，第一步可以先梳理哪种失败属于感知、动作策略、控制或复位，再决定增加哪种学习循环。该原则并不要求把 ENPIRE 的某套硬件或全部算法原样搬过来。

最后用六个问题检查理解：

  1. 为什么策略研究阶段要固定复位和奖励，而奖励设计又可以在设置阶段被 Agent 改进？
  2. 插销失败后，执行恢复、RL 更新和 Agent 修改代码分别改变了什么？
  3. 为什么示范缓冲区存在，不足以证明 RL 损失中有 BC 正则？
  4. 三维末端增量、十维动作格式和十四个执行关节分别属于哪一层？
  5. 99% pass@8、50/50 窗口与 17/20 检测准确率，分母为何不同？
  6. Git 共享、文字摘要和策略参数，各能保留哪种经验？

如果能沿着一条轨迹解释这些区别，就已经抓住了 ENPIRE 的主要机制：固定实验条件，明确改进对象，用真实反馈检验下一步。
