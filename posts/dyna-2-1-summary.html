The central idea

客户需要交出一项工作后可以离开。Dyna-2.1 的核心，是把可迁移的物理技能和能够持续调度的工作流智能体连接起来。

01 / PROBLEM

做对一个任务，还不等于接管一份工作

Dyna-1 曾连续叠餐巾 24 小时，但仍然需要人补充餐巾、移走成品。单步任务运行再久，只要上下游依赖人，完整流程仍会停下来。

洗衣房的要求更高：机器人要跨工位移动，处理不同高度的操作，根据机器状态切换任务，并在错误出现后恢复。

01 / LOAD装载与洗涤
02 / TRANSFER转移湿毛巾
03 / DRY烘干与卸料
04 / FOLD折叠与堆叠
05 / STORE搬运与上架

毛巾有顺序，机器人却需要在多个工序之间调度：洗衣机和烘干机独立运行，折叠任务必须能够暂停和继续。

因此，可靠性需要两条腿：减少错误，以及把可恢复的错误变成机器人自己能处理的分支。抓到两条毛巾、掉落物品、堆叠倾斜，都可能影响后续步骤，甚至让已完成的工作重来。

02 / SYSTEM

三个时间尺度，三个职责

Dyna-2.1 由硬件、动作学习和工作流推理共同组成。高层决定下一步，中层生成动作，底层协调身体；各层以不同频率运行。

Taku 选择轮式移动，围绕目标工作中更重要的伸展范围、操作精度与稳定性设计。它需要深入烘干机滚筒、接近地面货架，也需要向高处搬运。

身体比例接近成年人，便于跟随人类示范中的手腕、手肘和胸部运动。机械臂使用低减速比行星执行器，以支持更高的速度与加速度。

03 / LEARNING

URR：连接人类示范与机器人执行

URR（Unified Robot Representation）是统一的任务空间运动接口。它用手腕、手肘、胸部和底盘参考位姿描述动作，采用局部一致的坐标系；不同数据源可以包含不同身体部件。

它保留示范中的任务空间运动，把关节协调交给控制器。例如，直接把人的动作拟合成机器人关节，可能使手偏离接触物体的位置；URR 旨在避免这类动作标签与视频不一致的问题。

URR 是中间动作接口，不是高层规划器。编排器负责选择步骤，控制器负责具体的关节与底盘协调。

让人类数据进入机器人学习

官方称，改进版 Dyna-2 使用 100 万小时人类视频与机器人车队数据混合预训练。人类运动可训练策略，也可作为控制器的训练课程。

让旧数据跨越硬件迭代

保持上层动作接口稳定，硬件变化时主要重训底层控制器。动态差异仍然存在，因此还需控制器元信息提示与异步推理中的命令上下文。

控制器还要“适合被学习”。原文强调：总跟踪误差相同的控制器，可能一个振荡、一个平稳。振荡会损害模仿学习，因此他们把无振荡作为重要要求，并通过新示范持续扩大控制训练的覆盖范围。

04 / REASONING & MEMORY

记住发生过什么，才能决定接下来做什么

编排器建立在视觉语言模型上，并针对洗衣工作流分支做后训练。原文将一轮流程拆成 13 个决策点；其中一些依赖几分钟甚至几小时前的信息。

折叠期间检查机器状态

当洗衣机与烘干机工作时，机器人继续叠毛巾；同时判断何时应去处理完成的机器。

烘干结束，切换去卸料

完成当前折叠后，卸下烘干机中的毛巾，再把洗衣机中的湿毛巾转入烘干机。

根据记忆恢复折叠和堆叠

读取此前累计的折叠数量，继续工作；堆叠达到要求后，选择还有空间的货架上架。

检查结果，失败时选择恢复分支

决定重试、换方法或调整计划，再由动作策略执行。无法恢复时，流程会请求人工帮助。

TEXT MEMORY / 文本长期记忆已完成的步骤 · 门的开闭状态 · 机器运行状态 · 毛巾折叠数量 · 当前工作进度

这个分层设计把两类判断分开：折叠内部的动作检查由策略负责，跨工序的调度由编排器负责。编排器可以在策略继续执行时使用更多上下文和推理时间。

自主恢复是专门教出来的技能。原文展示了洗衣机旋钮与按钮受到人为干扰后继续操作，以及一次抓到两条毛巾后的恢复。这些演示支持特定恢复能力，不能推出覆盖所有异常。

05 / EVIDENCE BOUNDARY

展示了什么，还需要验证什么

这是一篇公司技术博客。系统机制和实验数字按作者自述整理；本文未独立复现实验，也未逐帧审查一小时演示视频。

本次发布

公司提供约一小时未剪辑的洗衣房工作流视频，称由 Dyna-2.1 自主执行；另外展示服务器操作、取饮料，以及特定干扰下的恢复。

技术披露

文章说明了 Taku、URR、强化学习全身控制、Dyna-2 策略、VLM 编排器和文本记忆之间的分工，并解释了多源数据与旧数据复用的设计。

数字归属

87% 零样本客户验收通过率是文章引用的此前 Dyna-2 固定工位结果，对照 Dyna-1 的 46%。它不是 Dyna-2.1 完整洗衣流程的成功率，也不是一小时工作流的验收结果。

部署阶段

作者明确把“带到真实客户现场并建立部署数据飞轮”列为下一步。本次工作流演示不能直接等同于真实客户现场已经实现长期无人值守。

尚缺验证

文章没有给出完整的跨日期、跨场地重复工作流统计，也未提供足以评估长期运营的平均无干预时长、吞吐、人工支持成本和单位经济性。编排器针对特定工作流做过训练，陌生流程的泛化仍需验证。

Reading takeaway · 综合判断

最值得关注的是：URR 把人类数据、动作策略与全身控制连起来，再由有记忆的编排器组织长流程。它提出了一条走向完整岗位自动化的技术路线；下一道验证门槛是客户现场的长期可靠性与运营成本。

作者也提出，评估重点应从单次任务成功率，扩展到机器人能在多长的工作流中持续运行而不需要人工干预。本文认为这一方向符合实际使用需求，但仍需明确时间长度、成功定义和重复试验协议。
