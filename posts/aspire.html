核心判断

ASPIRE 的实质，是把前沿 Coding Agent 组织成“上岗前自主踩坑调机的机器人系统工程师”。它用模块化视觉与运动规划工具链替代端到端黑盒试错，用可读可筛选的 Markdown 技能文档替代易遗忘的网络权重更新，在固定工站与多步几何编排任务上极具实用价值，但面对陌生环境的首次零容错交互仍受限于试错编译成本与物理复位条件。

Sim-to-Real 与真机闭环

跨本体迁移与在线还原魔方

由于技能库保存的是语义与几何层面的操作规范而非绑定特定仿真器的网络权重，仿真积累的技能可直接挂载至真实双臂 YAM 工作站（搭配 SAM3 感知服务与 cuRobo 规划服务）：

  • 真机调试加速：在真实机器人抓汽水罐（soda-can lifting）等任务上，挂载仿真技能库使推理 Token 消耗减少约 10 倍，显著降低真机试错轮次。
  • 真机双臂还原魔方（Rubik's Cube）：不完全依赖仿真，系统同样支持在真实双臂平台上直接运行在线探索闭环，自主修补柔性夹爪打滑、视角遮挡与交接旋转偏差，执行效率随交互轮次递进提升。

模式 1：move_hand 与 grasp_object 的权衡选择

Pattern 1
问题描述与适用时机
  • move_hand(pose, arm) —— 速度快、耗时可预期，但在贴近地面处的机械臂可达范围受限。
  • grasp_object(pregrasp, grasp, name, arm) —— 速度较慢，底层调用 cuRobo 逆运动学（IK）与运动规划器，可达范围更好，但存在卡死（Hang）风险。
  • 适用时机：在调用 sample_grasp_pose 获得候选位姿后决定如何执行抓取时，始终应用。
决策矩阵 (Decision Matrix)
场景优先使用备选回退 (Fallback)
地面物体（z < 0.1m），距离 ≤0.45mgrasp_objectmove_hand
地面物体，距离 0.5–0.6mmove_handgrasp_object
桌面 / 货架物体move_handgrasp_object
剩余时间预算 < 200s仅用 move_hand—
剩余时间预算 > 400s依次串行使用两者—
耗时实测数据（汽水罐 Soda 任务）
方法典型耗时最坏情况卡死风险
move_hand（预抓取 + 抓取）80–130s200s无 (None)
grasp_object150–265s619s+（卡死）有 (Yes)
代码模板：按位姿交错执行 (Interleaved Per-Pose)
for pose_idx, (pg, g) in enumerate(zip(pregrasp_poses, grasp_poses)):
    if success or time_left() < 60:
        break

    # 优先尝试 move_hand（速度快）
    for arm in [0, 1]:
        if success or time_left() < 60:
            break
        try:
            open_gripper(arm=arm)
            move_hand(pg, arm=arm)
            time.sleep(0.5)
            move_hand(g, arm=arm)
            time.sleep(0.5)
            close_gripper(arm=arm)
            time.sleep(0.5)
            lift_arm(arm=arm)
            time.sleep(1)
            if check_object_in_hand(arm=arm):
                success = True
                break
            else:
                open_gripper(arm=arm)
                lift_arm(arm=arm)
        except Exception:
            try:
                open_gripper(arm=arm)
                lift_arm(arm=arm)
            except Exception:
                pass

    # 若 move_hand 失败，立即尝试 grasp_object（切勿推迟到最后！）
    if not success and time_left() > 120:
        for arm in [0, 1]:
            if success or time_left() < 120:
                break
            try:
                open_gripper(arm=arm)
                grasp_object(pg, g, target_object, arm=arm)
                lift_arm(arm=arm)
                if check_object_in_hand(arm=arm):
                    success = True
                    break
                else:
                    open_gripper(arm=arm)
            except Exception:
                try:
                    open_gripper(arm=arm)
                except Exception:
                    pass
关键原则与实验证据

交错执行，切勿延后：在 v1（汽水罐）中，我们先跑完了所有位姿的 move_hand，把 grasp_object 留作最后兜底；结果 move_hand 耗去 789s，仅剩 61s，导致 grasp_object 被完全跳过。v2 改为针对每个位姿先试双臂 move_hand，失败后立即试双臂 grasp_object。

  • Seed 34（基线成功）：0.5m 处 move_hand 耗时 100s，SUCCESS；Seed 28（基线成功）：0.65m 处 grasp_object 耗时 220s，SUCCESS。
  • Seed 29（基线失败）：grasp_object 卡死 619s 超时；v3 修复后在 0.45m 处调用耗时 158s，SUCCESS。

模式 2：双臂遍历抓取 (Dual-Arm Grasp)

Pattern 2

大模型生成的代码常固定使用单侧手臂（arm=0 或 arm=1），在当前接近角下可能够不到物体。策略：始终对每个抓取位姿遍历左右双臂。 

for arm in [0, 1]:
    try:
        open_gripper(arm=arm)
        grasp_object(pregrasp, grasp, object_name, arm=arm)
        lift_arm(arm=arm)
        if check_object_in_hand(arm=arm):
            success = True
            break
    except Exception:
        open_gripper(arm=arm)
  • 证据：Seed 26 仅用 arm=1 失败；Seed 33 仅用 arm=1 失败（换 arm=0 修复）；Seed 35 仅用 arm=0 失败；成功基线中 Seed 32 用右臂、Seed 28 用左臂，无单一最优手臂。
  • 选臂启发式：左臂（0）更易够到偏左目标，右臂（1）更易够到偏右目标；不确定时优先尝试 arm=0。

模式 3：地面物体抓取 (Floor Object Grasping, z < 0.1m)

Pattern 3

地面高度物体（z < 0.1m）最难抓：手臂须同时水平前伸并下探，大幅压缩可达工作空间。

  • 执行策略：① 底盘导航贴近至 0.45m（而非 0.5m 或 0.6m）；② 首选 grasp_object（cuRobo IK）；③ 采用 ±90° 垂直逼近角改善手臂构型几何。
  • 为什么 move_hand 失败：0.6m 与 0.5m 处 grasp_z=0.094 均无法求解；0.5m 处虽能解出 grasp_z=0.160，但悬在罐顶上方 9cm 处导致抓空。Seed 29 在 0.45m 配合垂直角与 grasp_object 修复成功。

模式 4：抓取卡死缓解机制 (Grasp Hang Mitigation)

Pattern 4

cuRobo 规划器陷入僵局时，grasp_object 可能非确定性卡死 600s+，单次卡死即烧光预算。 

if time_left() > 120:  # 剩余时间不足 120s 时绝不调用
    try:
        grasp_object(pregrasp, grasp, object_name, arm=arm)
    except Exception as e:
        print(f"grasp_object error: {e}")
        open_gripper(arm=arm)  # 清理复位夹爪
  • 局限性：C++ 底层实现忽略 Python SIGALRM 信号，一旦启动无法强行中断；120s 仅为安全余量而非绝对保证（单次仍可超 300s）。

模式 5：check_object_in_hand 假阳性（瞬时抓稳但抬臂滑落）

Pattern 5
  • 现象：物体短暂夹住但在 lift_arm 过程中或之后滑落，check_object_in_hand 仍可能返回 true，而奖励函数要求物体仍在手中且高于初始高度（Seed 52、61 均出现返回 true 但 reward=0）。
  • 缓解：取决于夹爪摩擦与物体几何，无纯代码根治手段；若首次抓取报成功但任务未完成，应换另一组候选位姿对重试。

                EN · PATTERN 1
                move_hand vs grasp_object
                

                  move_hand is fast (80–130s, no hang risk) with limited floor reach; grasp_object uses cuRobo IK+motion planner with better reach (150–265s) but can hang 619s+. Interleave per-pose instead of deferring grasp_object until all move_hand attempts burn 789s.
                

              

              

                ZH · 模式 1
                快慢双策略按位姿交错
                

                  move_hand 快且不卡死但贴地手短；grasp_object 调 cuRobo 可达性强但可能卡死 619s+。核心铁律：针对单个位姿交替尝试，切勿先跑完所有位姿的 move_hand 烧光 789s 导致兜底被跳过。
                

              

            


            

              

                EN · PATTERN 2
                Dual-Arm Grasp
                

                  LLM code often hardcodes a single arm. Neither arm is universally better across approach angles (Seeds 26, 33, 35). Always iterate for arm in [0, 1] for every grasp pose; try arm=0 first when in doubt.
                

              

              

                ZH · 模式 2
                左右双臂工作空间遍历
                

                  大模型常偷懒写死单臂，易受接近角限制够不到目标。没有任何一只手普适占优，必须对每个候选位姿循环尝试 arm in [0, 1]，不确定时先试左臂 arm=0。
                

              

            


            

              

                EN · PATTERN 3
                Floor Object Grasping (z < 0.1m)
                

                  Horizontal extension + downward reach shrinks workspace. Navigate to 0.45m, use grasp_object (cuRobo IK) as primary, and try ±90° perpendicular angle. At 0.5m, move_hand only solves z=0.160 (9cm above the can) and misses.
                

              

              

                ZH · 模式 3
                地面低矮物体抓取几何
                

                  前伸叠加下探严重压缩可达空间。底盘需拉近至 0.45m，首选 grasp_object 强 IK，并采用 ±90° 垂直切入角，避免简单规划器在 0.5m 处解出悬空 9cm 假位姿抓空。
                

              

            


            

              

                EN · PATTERN 4
                Grasp Hang Mitigation
                

                  grasp_object can non-deterministically hang 600s+ and C++ internals ignore Python SIGALRM. Always check time_left() > 120 and wrap in try/except with open_gripper cleanup.
                

              

              

                ZH · 模式 4
                规划卡死预算守卫
                

                  grasp_object 可能非确定性卡死 600s+，且底层 C++ 忽略 SIGALRM 无法中断。调用前必须校验 time_left() > 120 并包裹异常处理复位夹爪。

              为什么一份 100% 在仿真里总结出的文档，上真机不仅没崩，反而省了约 10 倍推理 Token？

              如果是强化学习，下方左侧的“仿真器卡死怪癖”会同右侧的“物理几何规律”一起刻死在权重里。而在 ASPIRE 中，这份文档作为上下文参考（In-Context Guidance）提供给真机 Agent：大模型对照真机 API 文档时起到了天然语义过滤器的作用 —— 自动忽略不存在的函数名和超时数值，只提取右侧跨硬件成立的几何与状态机逻辑。
            


            

              

                仿真器工程怪癖 · Sim Artifacts（真机自动过滤）
                

                  1. 单次耗时百秒与 619s+ 规划死锁（模式 1 & 4）
                  真实 GPU 上 cuRobo 规划通常只需几十至几百毫秒；动辄 200s 乃至卡死 619s、C++ 忽略 SIGALRM，源于重度家庭仿真器（OmniGibson）在点云碰撞网格重建与物理步进同步上的工程瓶颈。
                

                

                  2. 评测预算守卫 time_left() > 120（模式 1 & 4）
                  针对仿真 Episode 限时机制设计的防御性刷榜逻辑，属于典型的评测环境适配（Harness Engineering）。
                

                

                  3. 特定随机种子与奖励判定器（全篇）
                  Seed 28/29/52 及 reward=0 直接绑定仿真评测集配置，在真实物理世界中并不存在对应接口。
                

              


              

                通用几何与状态机规律 · Transferable Laws（直通真机）
                

                  1. 低矮地面物体的运动学边界（模式 3）
                  抓地面物体（z < 0.1m）时水平前伸叠加下探会急剧压缩工作空间 —— 先拉近底盘距离（0.45m）+ 采用 ±90° 垂直切入角 + 警惕“悬空 9cm 假可达解”，在真实轮式双臂机器人上完全成立。
                

                

                  2. 左右双臂工作空间遍历（模式 2）
                  纠正代码模型“偷懒固定写单手”的惯性，对每个候选位姿遍历双臂校验可达性，直接减少真机单侧死角失败。
                

                

                  3. 瞬时闭合 ≠ 稳定抓取（模式 5）
                  夹爪闭合瞬间极易误判，必须在抬臂（lift_arm）克服重力后做二次确认；滑落时切换下一组候选抓取位姿对，而非原地重复死磕。
                

                

                  4. 单位姿快慢策略交错重试（模式 1）
                  避免单一策略连续失败耗尽重试窗口，是稳健机器人任务状态机的通用编排模式。
                

              

            

          

        

      


      
      

        05 / GENERALIZATION & DEPLOYMENT BOUNDARIES
        
工程落地冷思考：换成新场景新任务，还得摸索一阵子吗？

        

          把 ASPIRE 放到真实工程场景中评估，“要不要重新摸索”取决于“新”到了哪一层。按照任务变化幅度，可以清晰划出三条能力边界：
        


        
        

          
          
          
        


        


        

          

            最契合的工程定位
            
柔性产线换型 & 固定工站“自动驻场调机”

            

              在工厂工站换线、实验室自动化台面、标准化桌面清理或分拣工位中，任务目标固定但每次物体位置有局部波动。这类场景允许机器人在正式投产前花 1～2 小时自己在工位上试错踩坑，把 policy.py 调到高成功率，随后成千上万次直接复跑脚本 —— 实质上替代了昂贵的人类机器人工程师驻场写状态机的工作。
            

          

          

            当前短板与融合演进
            
开放家庭零容错场景 & 高频柔顺力控

            

              若把家庭机器人第一次推进陌生厨房，要求“不许摔坏茶具、不许人工复位、第一遍就把茶泡好”，现场写代码试错便来不及了；同时穿针引线、揉面团等毫秒级连续力控也难以用离散几何 API 表达。未来更现实的方向是“上层 ASPIRE 代码演化编排 + 底层高频 VLA / RL 原子控制器”的分层融合。
