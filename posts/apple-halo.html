HALO：基于仿真的感知型人形机器人全身自主控制

“Trained in homes that don’t exist. Deployed in homes it has never seen.”（在不存在的虚拟家庭中训练，零样本部署到从未见过的真实家庭。）

Part 01 · 项目博客与论文全景介绍
HALO 解决了什么核心痛点？整套系统是如何运转的？
核心命题：现有人形机器人能后空翻、能跳舞，但都是“敏捷的盲人”——无法走进一间从未扫描过的陌生客厅，听懂人话找到椅子坐下或钻过茶几。阻碍通用人形自主性的最大瓶颈是配对数据稀缺：用遥操作服（如 TWIST）或手持设备采集 1 小时“第一视角图像 + 语言指令 → 全身关节动作”至少耗费 1 小时人力。
HALO 的解法：用程序化仿真合成管线把数据规模与人类体力劳动彻底解耦（仅受算力约束），在 1,000 个虚拟房间自动合成视觉-语言-动作语料，并通过语义与物理分层解耦的全机载三层控制栈，实现了从未见过的真实家庭零样本全身交互。

1全机载三层自主架构（Onboard Autonomy Stack）

HALO 在改装后的 Unitree G1（29 自由度，整重 37.56 kg） 上实现了完全无外接电缆的端侧自主计算。感知在两个抽象层级分两次介入——前两层解决“语义问题”（去哪张椅子？怎么绕过去？），最底层解决“物理问题”（真实椅面到底有多高？落座如何不摔倒？）：

A · Orchestrator（任务编排器）
~0.5 Hz（约每 2 秒） 硬件：背部 Mac mini M4 Pro (64GB)
现成离线 VLM（Qwen3.6-35B-A3B，4-bit MLX）。接收人类自由语言指令（如 “Push box away”、“Crouch under the table, then sit on the chair”）与头部 120° 广角 RGB 画面，将长程请求拆解为原子子任务序列；闭环判断当前步骤成功则推进，失败则重试或插入前置动作。
↓ 下发单条标准化子任务文本（如 "sit down on the chair"）
B · Motion Generator（运动生成器）
~3 Hz（每 0.33 秒重规划） 硬件：背部 Mac mini M4 Pro (MLX)
非对称编码-解码器：冻结 Qwen3.5-2B 编码器 + 49.3M 参数 DiT 解码器（Flow Matching，15 步 Euler 采样，耗时 ~152ms）。根据当前 RGB 图像与子任务，每次生成未来 5 秒（150 帧 × 36 维：29 关节角 + 骨盆局部 3D 平移 + 4D 四元数） 全身运动学轨迹，其中前 0.5 秒（15 帧）锁定提交（Committed）以保证异步重规划无缝衔接。
↓ 通过千兆网口 ZeroMQ 流式下发 30Hz 全身运动学参考轨迹
C · Motion Tracker（物理跟踪器）
50 Hz 硬实时控制（PD 200 Hz） 硬件：机身原装 Jetson Orin NX
运行在 PREEMPT_RT 实时内核上的 C++ TensorRT 进程。融合躯干下视 55° 深度相机（经 LiteAnyStereo 双目重建为干净的 48×84 深度图）、IMU 与 30 步本体历史，在满足平衡、接触与电机力矩限制的前提下高频跟踪规划轨迹，输出 29 个关节位置目标。

2合成数据引擎：如何用算力凭空造出 300 小时配对数据？

博客通过四个交互站点拆解了在 250 张 H100 GPU 上运行 48 小时全自动产出的合成数据管线（共 6 大技能、162,698 条轨迹、296.3 小时）：

Station A · Kimodo + 33 Checks 运动学全身动作合成与几何质检

将任务拆解为带文本提示、路径点（Waypoints）和终点关键帧（Keyframe）的片段（如向前走 → 转身 → 坐下），调用动作扩散模型 Kimodo 批量采样候选轨迹，并用多达 33 项前向运动学几何校验（过滤脚底打滑、地面穿模、悬空跳变、关节超限）保留最高分轨迹。

Station B · Infinigen 1,000 Homes 程序化虚拟家庭构建与无碰撞放置

利用 Infinigen 生成 1,000 个训练房间（45% 客厅、30% 办公室、25% 卧室，边长 3.5–9.5m，含 20–80 件家具）及 178 个独立测试房间。提取 10cm 2D 占据栅格，在 SE(2) 空间采样旋转平移位姿 (x, y, θ)，保留轨迹与家具无碰撞（骨盆间距 ≥0.35m）的配置。

Station C · Baking + Fisheye DR 全局光照烘焙与鱼眼相机域随机化

先用 Blender Cycles 将每个房间的全局光照一次性烘焙为无光照自发光贴图，再在 Isaac Sim 5.1 中按真机标定的 OAK-1W 鱼眼内参（1280×800，下倾 25°）高速回放渲染，并施加 8 种视觉域随机化（运动模糊、椒盐噪声、强/暗光、冷/暖色调、绿偏色、高对比度）。

Station D · Imitation + 3-Phase RL 模仿学习与强化学习分治训练

使用合成的“第一视角视频 + 语言 + 全身动作”三元组，在 64 张 B200 上以 Flow Matching 模仿学习训练中层 Motion Generator；同时结合合成动作与重定向的 LAFAN1 人类动捕片段，在 4 张 H100（Isaac Lab）上通过三阶段强化学习训练底层感知型 Motion Tracker。

Part 02 · 四大核心技术追问深度拆解
看似都是常规模块，为什么组合起来效果如此惊艳？
总纲解答 —— 为什么“简单模块”跑出了惊艳效果？
HALO 没有迷信“用一个超大端到端 VLA 硬抗所有物理细节”，而是把问题边界切分得极其干净，并用严密的工程把模块交界处的裂缝全部堵死：
① 分层各司其职：高层只做离散工具选择，中层只管骨盆局部坐标系下的几何意图（不用懂接触力学），底层只管 0.1–0.6 秒内的物理平衡与局部深度适应（不用懂人类语言）；
② 真正吃到了场景规模红利：训练房间从 1 个扩到 1,000 个，单靠环境多样性就把 Sit 成功率从 43% 拉升到了 84%；
③ 消灭了异步与传感器的隐形断层：中层用 Training-time Chunking 消灭重规划跳变（24% → 84%），底层用神经网络双目匹配 + 电机系统辨识把 Sim-to-Real 误差压到了极致。
追问 1 高层任务编排模型（Orchestrator）用的是什么模型？有专门的后训练吗？

1. 具体模型：默认全机载离线运行在背部 Mac mini M4 Pro 上，使用的是阿里开源的 MoE 视觉语言模型 Qwen3.6-35B-A3B（4-bit 量化，基于 Apple MLX 框架推理）。得益于总参 35B、单 token 仅激活 3B 的稀疏架构，单次状态转移决策延迟仅 0.72 秒（与运动生成器共享 GPU 时约 1.46 秒）。系统也支持可选切换至云端大模型 API。

2. 有没有后训练？完全没有后训练（Off-the-shelf 零样本调用）！它之所以不微调就能稳定驱动机器人，靠的是“极度收窄的词表映射 + 闭环工具状态机”：

  • 把开放语言坍缩为 10 条固定指令：编排器只能从 Prompt 给定的 11 个受限函数（go_to_chair、go_to_box、go_to_human、follow、sit、crouch_under、crawl_through、sidewalk、push_box、stand、hold）中挑选，再查表翻译成下游生成器训练时见过的 10 条一字不差的标准短句，彻底帮中层小模型挡住了自由语言的多样性冲击。
  • 高频闭环监督工具调用：子任务执行期间，编排器持续读取最新相机画面及机器人当前骨盆高度（base_height）与偏航角（yaw），每次仅调用一个控制原语：
# Orchestrator 运行时闭环监督的 6 个原子工具（固定 System Prompt 常驻 MLX KV Cache）
set_plan(steps)        # 生成或重写最多 8 步的有序子任务计划（JSON Schema 强约束）
complete_step(success) # 判定当前步已完成（仅当机器人停稳且姿态恢复正常时允许调用），推进下一步
retry_step()           # 子任务提前停下但目标仍在前方可达处，原地重新触发当前子任务
insert_step(subtask)   # 当前路径被桌子/半开门挡住，动态插入前置动作（如 crouch_under）清障
ask_operator(question) # 视野丢失目标或场景存在歧义时，严禁盲猜，主动向人类发问
finish_mission()       # 全部子任务确认完成，结束整个长程任务
追问 2 全身运动生成器只用了 2B 且是冻结编码器，这真的能训出来吗？

不仅训出来了，而且可训练参数其实只有 49.3M（8 层 DiT 解码器，宽度 512，8 头）。它能跑通的核心原因有四点：

  1. 保留完整空间 Token 而非单向量压缩：输入图像虽缩放到 224×224，但模型提取了冻结 Qwen3.5-2B 最后一层的全部 64 个图像 Patch Token + 全部文本 Token（从 2048 维线性投影至 512 维），DiT 解码器通过 Cross-Attention 直接读取目标在视野中的粗略方位与距离。厘米级的最后接触精度交给底层深度 Tracker 兜底，无需 2B 编码器精确测距。
  2. 局部骨盆坐标系与离线特征缓存：输出的 150 帧轨迹全部相对于当前时刻骨盆坐标系表达（天然具备全局位置不变性）。因为编码器完全冻结，团队直接把 3,100 万个样本的 VLM 特征提前离线算好存盘，从而在 64 张 B200 上开出 5,120 的超大全局 Batch Size 高速训练 50 个 Epoch。
  3. Training-time Chunking + Flow Matching 解决异步跳变：每次重规划时，机器人已承诺执行的未来 P = 15 帧（0.5 秒）直接作为无噪 Clean Token（流时间标记 s = 1）拼在序列开头，网络只去噪后 135 帧（4.5 秒），从数学结构上内化了新旧规划的平滑连续性。

4. 更精彩的发现：作者其实试过全量微调 Qwen3.5-2B，结果差点“训废了”！（Appendix G-1）

✓ 冻结 Qwen3.5-2B（最终方案）

  • 保住真实世界零样本泛化：哪怕合成数据里“跟随人”只用了 1 个虚拟假人模型，上真机面对各种高矮胖瘦、不同衣着的真人照样全认识。
  • 严格听从语言指令：不会因为画面里有椅子就无脑坐下。
  • 推理轻快：Mac mini 上整套推理仅 152ms。唯一短板是对 39° 与 40° 这种极微小方位变化不够敏感。

✗ 微调 Qwen3.5-2B（踩中两大深坑）

  • 优势：保留了精细像素坐标，“跟随行人”时转向响应更灵敏顺滑。
  • 深坑 1（灾难性过拟合）：微调后上真机只认识长得像训练假人的人！被迫用 Hunyuan3D 生成大批不同 3D 人物重渲数据才救回来。
  • 深坑 2（视觉捷径忽略语言）：因为训练图有椅子大概率配“坐下”，模型学会了只看图猜动作、无视文本命令！被迫将 30% 训练图像涂成纯黑帧逼它读文本才修好。
追问 3 主流 System 0 全身 RL Tracker 几乎都不看视觉，HALO 是怎么把深度相机塞进 RL 的？

为什么必须看深度？以往通用全身跟踪器（如 OmniH2O、ASAP、BeyondMimic）默认地面平整或参考轨迹绝对准确。但在未建模的真实家庭里，中层单目 RGB 规划必然存在几厘米高度/距离误差——盲视 Tracker 会一屁股坐空摔倒，或对着空气挥手“假推箱子”（消融去掉深度后，Sit 成功率从 84% 降至 74%）。

为什么别人很难直接训出来？因为从零渲染深度跑多技能 RL，既会被渲染拖垮早期探索速度，又会因不同技能（走路 vs 爬行 vs 推箱子）奖励量级悬殊而互相破坏。HALO 在 Isaac Lab 中设计了三阶段渐进训练 + 双通道自遮挡渲染：

  • Phase 1 · 不看深度的分技能特权专家（PPO，单卡 8,192 环境）：按技能族分开训独立专家（平地移动/穿门/钻爬、推箱子、坐椅子）。专家完全不渲染深度图，直接读仿真器无噪特权状态 + 一张以双脚为高度基准的 17×11 局部高程图（1.6m × 1.0m），极速收敛；同时为推箱子加入手腕距离门控（0.3m 内）的物体位移奖励，杜绝空挥手骗分。
  • Phase 2 · 多教师精准路由蒸馏（DAgger，单卡 4,096 环境）：将所有冻结专家蒸馏进同一个只看机载输入的学生网络（4 层 2D CNN 编码 48×84 深度图 + 3 层 1D CNN 编码 30 步本体历史 + SimBa 残差 MLP）。采用 20% 专家 + 80% 学生的混合 rollout，每个环境严格路由给对应技能专家计算动作 MSE，避免多专家动作平均导致动作变形。
  • Phase 3 · 带深度渲染闭环的 Multi-Critic PPO 微调（4 × H100，16,384 环境）：开启深度闭环做 RL 微调以突破蒸馏上限。为解决“推箱子多了物体奖励导致总回报远高于走路”的梯度偏置，提出 Multi-Critic PPO：共享同一个视觉 Actor，但每个技能保留独立的特权 Critic，并在各自技能 Batch 内独立标准化 Advantage（均值归零、方差归一）后再更新共享策略。
  • Two-Pass Warp Ray-caster 还原手脚自遮挡：普通仿真深度投射往往忽略机器人自身模型，导致低头看时能“透视”自己的手臂和大腿。HALO 用双通道 NVIDIA Warp 同时求交场景网格和机器人实时连杆网格取最近点，让策略在爬行、深蹲、推箱子时真实学会处理自身肢体遮挡。
追问 4 它到底用了什么仿真器？Sim-to-Real 为什么能做到几乎零掉点（91% → 91%）？

1. 四套仿真引擎协同分工（而非单一仿真器）：

仿真/渲染引擎 承担环节 为什么选它？
Blender 5.2 (Infinigen + Cycles) 房间生成与光照烘焙 Cycles 离线光追逐帧渲染 3,200 万帧太慢（13.2 秒/帧），因此仅用 Cycles 将每个房间的全局光照一次性烘焙进物体自发光贴图（38.5 分钟/房），新视角平均像素误差仅 1.5%。
Isaac Sim 5.1 第一视角鱼眼 RGB 合成 加载烘焙贴图后，以 56–87 ms/帧的高速渲染匹配真机 OAK-1W 鱼眼内参的 1280×800 视频（注：Push 任务在 MuJoCo 渲染）。
Isaac Lab 2.3 (+ Warp) 底层 Tracker 三阶段 RL 支持单机多卡最高 16,384 个并行物理环境与 25Hz GPU 双通道深度光线投射。
MuJoCo 上机前全栈闭环 Sim-to-Sim 运行与真机完全相同的多进程节点与通信中间件，按真实物理时钟把 152ms 模型推理延迟纳入闭环评测。

2. 把 Sim-to-Real 压到零掉点的五大“魔鬼工程细节”（Appendix C-4 & G-2）：

  1. 深度传感器“反向对齐”——用 AI 修复烂真机传感器：G1 原装 RealSense D435i 自带立体匹配充满红外散斑噪点与黑洞。团队没有在仿真里硬拟合脏噪声，而是直接关掉真机 D435i 的主动红外散斑投射器，把 30Hz 原始左右红外图喂给 Orin NX 上 TensorRT FP16 加速的轻量双目模型 LiteAnyStereo（7.6M 参数），在真机端直接算出如仿真般干净稠密的深度图（缺失像素映射至 2.5m 远平面，取 log(1+d)），从源头抹平了深度视觉鸿沟！
  2. 精细电机系统辨识（SysID）与膝盖再生制动保护：开源 G1 URDF 漏了电池重量、低估了髋部转子惯量，且真机电机实测刚度仅标称值的 78%–90% 并带 25–30ms 环路延迟。团队在背负 Mac mini 的真机（37.56 kg）上跑开环轨迹辨识拟合参数，将关节跟踪误差直接砍掉 62%（26.9% → 10.1%）；按转子惯量解析设定统一 10Hz 自然频率 PD 增益，并专门加入膝关节负机械功率（再生制动 >150W）惩罚，防止深蹲/坐下时触发硬件驱动器过流断电。
  3. “厚绒地毯 vs 光滑木地板”地面柔顺度随机化：只在刚性地面训出的策略踩上真实家庭的厚地毯时，脚会陷进绒毛 1–2 cm，策略误判为身体倾倒而疯狂碎步乱踩。Phase 3 专门随机化了地面接触刚度（1.3–6.5 kN/m）与阻尼，配合静立防滑惩罚，实现了地毯、瓷砖、滑木板和户外水泥地通吃。
  4. RGB 烘焙消反光 + 冻结 VLM 抗域偏：烘焙前将所有木质家具设为哑光材质（误差减半）并移除天花板防死黑，叠加冻结 Qwen3.5-2B 原生强大的跨域视觉鲁棒性。
  5. 两级渐进域随机化 + 硬实时 C++ 进程：Phase 1/2 保持窄随机化防止专家动作保守，Phase 3 才围绕 SysID 真值放宽延迟（15–40ms）与物理扰动；真机控制环锁死独立 CPU 核（SCHED_FIFO）、零动态内存分配、无锁三缓冲（Lock-free Triple Buffers）通信，彻底消灭软件抖动。
Part 03 · 延伸洞察与幕后真相
还有哪些没问到、但对做具身智能极具启发的事情？
洞察 01 · 合成数据的真实边界

解放了“数据采集员”，但没解放“任务工程师”

翻看附录 Table IV 会发现，6 个技能并非靠一句文本凭空生成：Sit 的落座关键帧抠自真机关节日志 + 33 条手写几何规则；Crawl/Crouch 先拿手机拍真人钻桌视频，经 GVHMR 提 3D 再人工手调 6 个关键帧；Push 后半段直接拼了一段真人动捕录像。HALO 真正跑通的是“极少量人类种子先验（1 条视频/几个关键帧） × 程序化放大 5 万倍”，每加新技能仍需人工写规则与关键帧。

洞察 02 · 长程掉点的真正死因

多任务掉到 50%–60%，输在“交接视野盲区”

单任务真机高达 91%，但 Crouch → Go-To → Push 真机掉到 50%。60% 的失败并非 VLM 规划出错，而是钻出桌子站起时头部朝向偏了，下一个目标箱子恰好不在 120° 视野内（或正对沙发坐错了位置）。由于中层模型无历史空间记忆（Spatial Memory），且缺少“原地转圈搜寻目标（Turn-in-place Search）”恢复原语，目标一出画链条即断。

洞察 03 · Apple 式端侧算力压榨

背着 Mac mini 上真机 + 单 GPU 层间抢占调度

相比笨重高功耗的 x86 工控机，64GB 统一内存的 Mac mini M4 Pro 轻松同时装下 35B 与 2B 模型。团队在 MLX 上手写了单线程调度器 halo_serve：当 333ms 周期的运动生成器到点时，直接在 35B 编排器神经网络层与层之间暂停抢占，优先算完运动规划（合跑延迟仅从 152ms 微增至 155ms），同时保底留给编排器 60% GPU 时间防饿死。

洞察 04 · 架构下一代演进方向

中底层“36 维窄接口悖论”与触觉缺失

作者在结论中坦承两大上限：① 中层传给底层的只有 36 维关节/骨盆轨迹，Tracker 完全不知道自己伸手是为了推箱子还是维持平衡，未来需传递“期望外部世界发生的状态变化”；② 全身无力觉/触觉反馈，一旦落座最后时刻椅面离开相机视野或物体被遮挡，只能靠惯性盲做，复杂灵巧接触亟需触觉融合。

洞察 05 · 数据资产解耦设计

存“随机种子 + 2D 位姿”，而不是存几百 TB 死视频

很多合成数据集存成渲染好的视频，一旦换机器人相机内参或改安装俯仰角就全废了。HALO 把每条数据存为极轻量的 (房间 Seed, 动作轨迹, 放置位姿 x, y, θ)，配合跨引擎误差 <1% 的自发光烘焙贴图——未来换新机器人、换双目相机或换物理仿真器，只需重新高速光栅化回放一遍即可复用全部数据。

洞察 06 · 真机 RL 选模铁律

“仿真总 Reward 高低”跟真机稳不稳几乎无关

附录 G-2 给出了一条极具实战价值的经验：在挑 Checkpoint 上真机时，仿真原始总分相关性很弱；真正决定真机成败的核心指标是动作平滑惩罚（Action-rate Smoothness，||a_t - a_{t-1}||^2）。若放任高频微幅动作，上真机遇到 25–30ms 延迟与关节静摩擦耦合，脚踝和手腕会立刻产生刺耳的高频自激啸叫。
